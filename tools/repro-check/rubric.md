# Rubric: is this reproduction package ready to post?

## Checks

Read the entire issue, claim, and report before grading. Judge observable outcomes, not heading counts or confident wording. These are full-package checks unless explicitly marked claim-only applicable.

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Specific claim | Candidate claim read against the issue body and thread; evidence guide Comms. Claim-only applicable. | The claim identifies the reported trigger, affected behavior, or relevant component and gives a concrete investigation/reproduction next step or reports a concrete completed investigation. It is not interchangeable boilerplate, a bare request for assignment, or a demand that maintainers fix it. | required |
| Recorded environment | Repro report's version/platform/configuration record against the issue's target and repo template; evidence guide Environment. | The tested project version or revision and behavior-relevant runtime, platform, configuration, and install details are stated sufficiently to identify the tested setup. Material differences from the reporter's setup are acknowledged. Require details that affect this reproduction or are explicitly requested by the repo, not irrelevant hardware inventories. | required |
| Rerunnable path | Report's setup, commands/UI actions, input/fixture contents, and prerequisites; evidence guide Steps. | A stranger can recreate the stated starting conditions and run through the trigger using the posted information and explicitly referenced public inputs. Required fixture contents, flags, configuration, and meaningful setup steps are available; no hidden local files or omitted essential steps. A minimal reproducer is sufficient; no minimum step count. | required |
| Target-matched evidence | Report's actual output/logs/screenshots or explicit observed UI state compared with the issue's trigger, expected behavior, and failure signature; evidence guide Behavior shown. | The report contains concrete observed evidence from exercising the issue's relevant trigger. A reproduced outcome shows the reported symptom, not an adjacent parse/setup/network error that prevents reaching it. A cannot-reproduce outcome passes when the same relevant trigger was attempted and evidence shows the observed nonfailure. Mere assertions such as "same error" or an unrelated failure are insufficient. | required |
| Honest conclusion | Claim and report assertions compared with the supplied observations; evidence guide Honesty. In claim-only mode assess only assertions present in the claim. | Statements stay within the evidence: distinguish observation from suspected cause, reproduction from cannot-reproduce, and local results from broader claims. Do not claim a successful reproduction when the shown behavior differs. A prospective claim may promise investigation and a report without asserting any completed run. | required |
| Repo conventions | Repo-facts template and contribution policy against candidate comments; live contributor docs/templates and voice guide; evidence guide Comms. Claim-only applicable for requirements that apply before reproduction. | The comments supply applicable explicitly requested information and satisfy stated contribution conditions, including AI-use disclosure where required. Silence about AI imposes no new disclosure requirement. The writing contains no insults, pressure, or unsupported demands. In live mode it also follows the personal voice guide. A claim-only draft need not supply a future report's environment or logs. | required |

## Verdict rule

Accept (ready) only if every applicable required check passes. A fail or unclear on an applicable required check means reject (hold). In live claim-only mode, Recorded environment, Rerunnable path, and Target-matched evidence are unclear with evidence "not yet applicable: claim-only draft" and excluded from the verdict. Apply the claim-only portions of the other checks. In eval mode and live full-package mode all checks apply. Report every check. Honest, evidenced cannot-reproduce is eligible for accept. A preferred check, if added, never changes the verdict. Voice-guide rules apply only in live mode through Repo conventions.
